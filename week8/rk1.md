# РК1: вопросы и ответы по темам недель 1–7

> Конспект для подготовки к рубежному контролю. Ответы краткие, со ссылками на практику из репозитория.

## Неделя 1. Вход в Web3: первая транзакция

**1. Чем блокчейн отличается от обычной базы данных?**
Данные хранятся у множества независимых узлов, изменения принимаются через консенсус, записи нельзя тихо переписать задним числом. Доверие обеспечивается криптографией, а не одним владельцем сервера.

**2. Что такое кошелёк и keypair?**
Keypair — пара ключей Ed25519. Публичный ключ (base58, 32 байта) — адрес аккаунта; приватный ключ подписывает транзакции. Кошелёк хранит ключи и подписывает от имени пользователя. Приватный ключ (`id.json`) никогда не публикуется — поэтому он в `.gitignore`.

**3. Что такое лампорт и сколько их в 1 SOL?**
Минимальная единица SOL: 1 SOL = 1 000 000 000 лампортов.

**4. Зачем нужны devnet, testnet и mainnet-beta?**
Mainnet — реальные деньги. Devnet — сеть для разработчиков с бесплатным SOL через airdrop/faucet. Testnet — для тестирования самих валидаторов и обновлений сети.

**5. Что можно увидеть в Solana Explorer по подписи транзакции?**
Статус, слот, комиссию, подписантов, список аккаунтов, инструкции, изменения балансов и логи программ.

## Неделя 2. Как работает Solana (Transaction Detective)

**6. Из чего состоит транзакция?**
Из подписей и сообщения (message): заголовок, список аккаунтов, recent blockhash и инструкции. Каждая инструкция = program id + список аккаунтов (с флагами signer/writable) + данные.

**7. Зачем нужен recent blockhash?**
Защищает от повторной отправки (replay) и ограничивает время жизни транзакции (~150 блоков, около минуты).

**8. Что такое Proof of History?**
Криптографические «часы»: последовательная цепочка SHA-256, доказывающая порядок событий во времени. Валидаторы договариваются быстрее, потому что порядок уже доказан. Консенсус поверх — Tower BFT (PoS).

**9. Почему Solana может исполнять транзакции параллельно (Sealevel)?**
Транзакция заранее объявляет, какие аккаунты читает и в какие пишет. Транзакции без пересечения по writable-аккаунтам выполняются одновременно.

**10. Из чего складывается комиссия?**
Базовая комиссия 5000 лампортов за подпись + опциональная priority fee (compute unit price × лимит CU).

**11. Лимиты транзакции?**
Размер — 1232 байта; по умолчанию 200 000 CU на инструкцию, максимум 1.4 млн CU на транзакцию.

## Неделя 3. Rust для Solana-разработчика

**12. Что такое ownership и borrowing?**
У каждого значения один владелец; при выходе владельца из области видимости память освобождается. Ссылки `&T` (сколько угодно для чтения) и `&mut T` (одна для записи) — заимствование без передачи владения. Проверяется на этапе компиляции.

**13. `Option` и `Result` — зачем они?**
`Option<T>` — значение может отсутствовать (`Some`/`None`), `Result<T, E>` — операция может завершиться ошибкой (`Ok`/`Err`). Оператор `?` пробрасывает ошибку вверх. В Anchor все инструкции возвращают `Result<()>`.

**14. Почему в смарт-контрактах важна проверенная арифметика?**
Переполнение u64 может создать токены «из воздуха». Используем `checked_add/checked_mul` или u128 для промежуточных значений; в release включено `overflow-checks = true`.

**15. struct, enum, trait, derive — кратко.**
`struct` — данные с полями, `enum` — один из вариантов, `trait` — общий интерфейс поведения, `#[derive(...)]` — автогенерация реализаций (например `Clone`, `Debug`, `InitSpace`).

## Неделя 4. Первая Solana Program

**16. Что такое программа в Solana и чем она отличается от контракта в Ethereum?**
Программа — исполняемый аккаунт без собственного состояния (stateless). Данные хранятся в отдельных аккаунтах, которые передаются в инструкцию.

**17. Что такое entrypoint?**
Функция `process_instruction(program_id, accounts, instruction_data)`, через которую рантайм вызывает программу.

**18. Модель аккаунтов: какие поля у аккаунта?**
`lamports`, `data`, `owner` (программа-владелец), `executable`, `rent_epoch`. Менять данные и списывать лампорты может только owner.

**19. Что такое rent и rent-exempt?**
Плата за хранение данных. Аккаунт с балансом ≥ минимума для его размера (≈ 2 года аренды) освобождён от неё — сейчас все новые аккаунты обязаны быть rent-exempt.

**20. Как обновить программу?**
Upgradeable loader: программа указывает на programdata-аккаунт, upgrade authority может загрузить новую версию байткода по тому же Program ID.

## Неделя 5. Anchor Framework (Counter)

**21. Что даёт Anchor?**
Макросы `#[program]`, `#[derive(Accounts)]`, `#[account]`: автоматическая десериализация и проверки аккаунтов, дискриминатор, IDL и TypeScript-клиент.

**22. Что такое дискриминатор?**
Первые 8 байт аккаунта (и данных инструкции) — хеш имени типа. Не даёт подсунуть аккаунт другого типа. Поэтому `space = 8 + ...`.

**23. Основные ограничения (constraints) в `#[account(...)]`?**
`init`, `payer`, `space`, `mut`, `seeds`, `bump`, `has_one`, `constraint = ...`, `close`, `address`, `token::mint`, `mint::authority`.

**24. Что такое IDL?**
JSON-описание интерфейса программы (инструкции, аккаунты, типы, ошибки). Из него клиент строит вызовы `program.methods.x().accounts({...}).rpc()`.

**25. Как объявить свою ошибку?**
`#[error_code] enum MyError { #[msg("...")] Variant }` и `require!(cond, MyError::Variant)`.

## Неделя 6. Accounts, PDA и архитектура программ

**26. Что такое PDA?**
Program Derived Address — адрес, выведенный из seeds и program id, лежащий вне кривой Ed25519, поэтому у него нет приватного ключа. Подписать за PDA может только программа через `invoke_signed` с теми же seeds.

**27. Что такое bump и canonical bump?**
Число 255…0, добавляемое к seeds, чтобы адрес оказался вне кривой. Canonical — первый подходящий начиная с 255; его сохраняют в аккаунте и проверяют `bump = account.bump`.

**28. Как обеспечить «один профиль на пользователя»?**
Seeds `["profile", user_pubkey]` — адрес уникален для пользователя, повторный `init` упадёт.

**29. Что проверяет `has_one = authority`?**
Что поле `authority` в аккаунте совпадает с переданным аккаунтом `authority` (а он — `Signer`). Защита от чужих изменений.

**30. Зачем `#[derive(InitSpace)]` и `#[max_len]`?**
Автоматически считает размер аккаунта; для `String`/`Vec` нужно указать максимальную длину.

## Неделя 7. SPL-токены и Token program

**31. Что такое mint и token account?**
Mint — аккаунт токена: supply, decimals, mint authority, freeze authority. Token account хранит баланс конкретного mint для конкретного владельца (owner).

**32. Что такое ATA?**
Associated Token Account — PDA от `(owner, token_program, mint)` в Associated Token program. Стандартный адрес кошелька для токена.

**33. Token program vs Token-2022?**
Token-2022 — новая программа с расширениями (transfer fee, metadata, interest-bearing, non-transferable и др.). В Anchor с обеими работают через `token_interface` и `InterfaceAccount`.

**34. Чем `transfer_checked` лучше `transfer`?**
Дополнительно передаются mint и decimals — программа проверяет, что сумма указана в правильных единицах. Для Token-2022 обязателен.

**35. Что такое CPI?**
Cross-Program Invocation — вызов другой программы из своей (например Token program для перевода токенов). Если подписать должен PDA — `CpiContext::new_with_signer(..., signer_seeds)`.

**36. Как выпустить токены через программу?**
Сделать PDA mint authority и вызвать `mint_to` через CPI с seeds этого PDA. Именно так vault выпускает share-токены.
